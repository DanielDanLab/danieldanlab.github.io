## Handling electronic text

### Introduction {#introduction-1}

Text mining and analytics provide marketing analysts with various tools
for analyzing large volumes of textual data (Guyt, Datta, and
Boegershausen 2024). These applications and the important role they play
were outlined in the introduction. In this section, we will focus on the
technical aspects of text acquisition, which typically takes a
considerable length of time, and it is important to acknowledge that
data collection and preparation represent a significant portion of a
project's duration, often up to 80
processes can significantly reduce the frustration and inefficiency
inherent in the acquisition of textual data (Frye and Schmitt 2020).

A large proportion of data available on the internet is unstructured,
(cf., Gandomi and Haider 2015; Wedel and Kannan 2016; and Boegershausen
et al. 2022). This means it is not organized in a tabular format or
within a database, and lacks a predefined structure. The primary types
of data requiring transformation are text and images. Since computers
operate more effectively with structured data, converting them from
unstructured to structured formats is critical in the analytical
process. Therefore, before commencing data collection, it is essential
to consider several fundamental questions. The foremost concerns the
format of the data to be collected. This leads to the realization that
data, in our case text, can be stored in various file types, such as
comma separated value (CSV) files, which are appropriate for this task.
Additionally, it is good to understand the relationships within the
data, the number of sources, and their acquisition methods. We speak
using words, but it is through written text that we leave our imprint on
the future.

Humans continuously generate text in various forms, ranging from
physical mediums such as letters, articles, diaries, books, and other
written formats, to virtual ones stored in file types such as .**txt**,
.**doc**, .**docx**, .**pages**, .**pdf**, and .**odt** files, among
others. Additionally, there are file formats with more or less familiar
extensions. In text analysis or analytics, having documents in an
electronic format is imperative, as it allows the text to be structured
and manipulated easily. Consequently, acquiring virtual text is
preferable, but there are methods to convert printed text into
electronic documents. Electronic text can be derived from printed
material through a two-step process. The initial step involves
digitization, achieved by scanning or photographing the documents. The
subsequent step is to extract text from these images, using optical
character recognition (OCR) systems. This process is often lengthy and
prone to errors (Srihari 1985), requiring specific software and human
intervention for quality assurance. Proofreading is critical, requiring
meticulous attention to detail to ensure the transformed text accurately
reflects the original. This procedure applies to standard printed text,
but the challenge intensifies with handwritten documents.

Mass digitization projects have been, and continue to be, significant
endeavors. Official initiatives like Europeana, backed by the European
Union, have created digital platforms housing millions of items. Another
notable project is that of Google Books, launched with the ambitious
goal of digitizing the world's books and making them accessible online
(Thylstrup 2019). A significant aspect of this project was the use of
OCR technology, which converted the scanned images of books into
machine-readable text. However, this project faced legal challenges from
authors and publishers until 2016, when Google won a series of important
legal battles and it was allowed to proceed with its scanning efforts
(Rimmer 2017). Today, a number of projects and partnerships give
research groups access to this extensive database to carry out in-depth
text analysis.

For those not requiring access to rare or non-digital textual sources,
using existing electronic versions is a practical approach. However,
although there are official repositories, shadow libraries do exist and
it is important to be mindful of the copyright laws in your region, as
not all digitized texts are freely available for research or other
purposes.

Some ways to obtain electronic text are the following: (i)
self-generated text, (ii) manual copy and paste, (iii) direct text
downloads, (iv) web scraping, and (v) utilizing ready-to-use datasets.
These are among the most common approaches, see
Figure [1.1](#fig-textdata){reference-type="ref"
reference="fig-textdata"}. Manual copy and paste is a straightforward
yet time-consuming method, ideal for small amounts of text. Directly
downloading text files, such as in **pdf** format, **docx** format, or
plain text files, is efficient for accessing large documents or books
already in a digital format. Scraping text from documents with various
file extensions often requires specialized software or scripts,
especially when handling large volumes of data or complex formats. On
the other hand, web scraping ranges from the simple extraction of
specific pieces of text from web pages to more advanced scraping that
navigates web pages and handles dynamic content. Lastly, ready-to-use
datasets from online repositories are a convenient source, as these are
often well-structured and ideal for analysis without extensive
preprocessing. Next we describe these common ways to obtain textual
data.

### Copy and paste

The simplest method of obtaining text that is not self-generated is
through copy-and-paste. This involves copying text from various sources
and pasting it into a simple text file stored locally on your computer.
It is a three-step process: selecting the text, mainly with the help of
your mouse, copying it, and then pasting it into a recipient file. You
can paste different portions of text consecutively onto the same text
file, making this procedure a primitive form of scraping. The procedure
is similar in all operating systems, such as MacOS, Windows, or Linux,
with minor differences in the commands and text editing applications
used. Here you have the procedure detailed for the most common
commercial operating systems:

*First, open the source document or webpage from which you wish to copy
text.\
*Click and drag your mouse over the text to highlight it.\
*On OSX, press Command + C to copy the highlighted text; on Windows, use
Ctrl + C.\
*Next, open a text editing application. For MacOS, use TextEdit; for
Windows, use Notepad. Note that TextEdit defaults to rich text mode. To
save your file as a .txt file, convert it to plain text by going to
Format in the menu bar and selecting Make Plain Text (or use the
shortcut Shift + Command + T).\
*Click inside the document and press Command + V on MacOS, or Ctrl + V
on Windows, to paste the copied text.\
*To save the file, click File \> Save (or use Command + S on MacOS, or
Ctrl + S on Windows). Name your file, for instance, "copied_text.txt".
Navigate to the desired folder within your working directory. If you're
looking for a specific folder such as 'data' and it does not exist,
create it. Finally, click Save.

This method is straightforward and does not require specialized
software, making it an excellent starting point for anyone new to data
collection.

This is how you import the file into R and visualize the text.

### Downloaded text

For a marketing practitioner, sourcing documents which are ready for
analysis is not always straightforward. For example, literature students
have the advantage of accessing many out-of-copyright texts available on
the internet. Alongside well-known resources like Google Books and
Europeana, they (or anyone else) can explore sites like the Gutenberg
Project, Internet Archive, Open Culture, Hathi Trust, ACLS Humanities
E-Book, National Digital Library of India, Gallica, Wikisource,
Runiverse, as well as many others. These platforms offer extensive
collections of books and freely accessible texts, ideal for downloading
and importing into R. The benefit of using simple text is that it allows
for imports from these websites, providing an excellent opportunity to
start developing text analytics skills. The goal is to have the text in
a format that lends itself to structured analysis.

Fortunately, collections of documents are already prepared in structured
formats such as CSV or zipped CSV files. These are often found on
platforms like Kaggle, GitHub, and the repositories of various research
institutes. When dealing with documents in compressed formats like
**.gz** or **.zip**, it is advisable to decompress them first before
importing them into R. Conversely, files in formats like **.csv** or
**.xlsx** can be imported directly from the internet via a secure HTTPS
connection. Downloading files over an insecure HTTP protocol is not
recommended for security reasons. Direct-internet import can be
cumbersome and prone to errors for files with substantial amounts of
data. Hence, it is preferable to download these files to your local
machine first and then import them into R.

The `df` dataframe can be sliced both horizontally and vertically to
suit your needs. The general syntax for this operation is
`df``[``rows, columns``]`. In this structure, the brackets encompass the
entire dataframe, and the comma separates the rows from the columns, in
specific order. To select the first row along with all its columns, you
would use d`f``[``1, ``]`, where the (empty) space after the comma
signifies the inclusion of all the columns. Similarly, to select
specific rows and columns, for example, rows 3 to 5 and columns 2 to 9,
you would use `df``[``3:5, 2:9``]`.

#### Common file-type extensions

What if the file you need to analyze does not have a `.csv` extension?
In such instances, the `readtext` package (Benoit and Obeng 2020) is
handy. It is designed to read and extract text from a variety of file
formats, including **.doc**, **.docx**, **.html**, **.json**, **.pdf**,
**.rtf**, **.tab**, **.xls**, **.xlsx**, **.xml**, and several other
related extensions. This versatile function not only extracts the text
but also retrieves the document's metadata, and it can handle multiple
file types simultaneously. The data extracted is stored in a dataframe,
our preferred tabular data format. As a side note, when importing data
into R, it is not uncommon to encounter issues with character encoding.
In such cases, check the solutions suggested in the introduction.

The `readtext` package relies on other packages for specific file types:
`pdftools` (Ooms 2020) for **.pdf** files and `antiword` for **.doc**
documents. Installation on Windows and MacOS is typically
straightforward. However, Linux users might face challenges,
particularly with `pdftools`, which requires a development library. On
Debian/Ubuntu and similar systems, this issue can be resolved by
installing the `libpoppler` development library. Other Linux
distributions with different package management systems, like those
using `rpm` package management, have similar solutions.

and its `read.spss()` function. In the next section, we will tackle more
advanced procedures to structure data from the internet effectively

### Scraping for data

It usually requires a more elaborate procedure to collect customer
opinions and other user-generated content, as they are typically
embedded within specific web pages. How do we collect reviews about a
specific product or service? Many companies, such as Airbnb, Amazon,
Booking.com, TripAdvisor, Trustpilot, and Yelp, host these data on their
websites. Similarly, opinion-based text from social-media platforms like
Twitter, Facebook, and Instagram can be valuable. We can access this
data through a process known as web scraping (Khder 2021). As the term
suggests, this involves extracting data from a surface. In a digital
context, it refers to the technique of copying data embedded in an
unstructured way within HTML tags to a structured format which suits the
needs of data analysts, such as a CSV file. What can we scrape from web
pages? Essentially anything digital: text, numbers, images, and
metadata. For instance, in the context of online product feedback, we
can collect customer reviews, product ratings, customer nicknames,
labels, dates, and other related data or metadata. All this can be
transformed into useful information for analysis and knowledge
extraction. Researchers in a number of fields such as economics (Cavallo
2012; Hillen 2019), psychology (Landers et al. 2016), agriculture (Yang,
Wilson, and Wang 2010), and the hotel industry (Han and Anderson 2021),
as well as geographic data acquisition (Brenning and Henn 2023), obtain
data through scraping. Web scraping for consumer research (Boegershausen
et al. 2022) plays a significant role too. There are several methods and
tools which facilitate the downloading and collection of data. Some of
them must be built specifically for the fields in which they are used
(Bonifacio et al. 2015), while others are more generic, such as Outwit
(2024), Fminer (2024), or Parsehub (2024). Some methods need to be
tailored to specific projects and frequently use computer languages such
as Java, Python, or R to carry out their data crawling. These tools
change data from an unstructured into a structured form, making them
ready for further analysis. It is important to note that data, mainly
text data, are often the core business of some companies, and they may
try to block or hinder automatic parsers or robots from scraping and
collecting information (Hirschey 2014; Poggi et al. 2007). Technically,
there are two main ways to scrape internet data: an application
programming interface (API), for example \[sturm2017\], or
document-object-model (DOM) parsing (Radilova et al. 2022). APIs,
provided by platforms such as Twitter, Facebook, and TripAdvisor, offer
well established procedures for obtaining data in predefined formats
such as **.csv**, **.xls**, or **.xlsx**. On the other hand, DOM parsing
is carried out through programming with scripts and requires
considerable effort. Additionally, some programs or plugins facilitate
the retrieval of information without an extensive knowledge of
programming.

#### Data from social media, the API concept

In the land of social media, there have been winners and losers. Some
social-media platforms, once ubiquitous, have now turned into little
more than websites, such as Myspace, or were entirely discontinued by
their creators, like Orkut and Google+. A few, however, have stood the
test of time: X (formerly Twitter), one of the most scraped social-media
platforms, Facebook, LinkedIn, Reddit, are just a few of these. Others
are new or emerging, such as TikTok. No matter their current status,
their content can be a valuable source of data. Let us briefly consider
them and the collection of their data through an API.

Twitter's name was inspired by how birds communicate, with short,
high-pitched calls or sounds directed to an audience which understands
those messages. The titular company debuted in 2006. Now rebranded as X,
it is well known for its micro-blogging consisting of short and concise
messages (Murthy 2018). This model of communication is both efficient
and information-dense. Messages, called tweets, have several key
elements: **addresses** (usernames marked by @), **text** (limited to
**280** characters), **hashtags** (marked by **\#** to denote topics),
and types of interaction like **replies**, **mentions**, and
**retweets**.

Data from X and other social media are particularly interesting for
marketing analysts because it has been, and continues to be, used
extensively for viral advertising (Tellis et al. 2019). It has strong
user engagement, a solid user base, and supports many languages.
Moreover, it contains vast amounts of real-time data. The mix of user
behavior and competitor strategy is crucial for understanding and
analyzing marketing. It is an ideal place to monitor influencers' ideas
and opinions, understand why they are followed, and use this information
for marketing purposes: for example, knowing how your brand is perceived
on this social-media platform. Learning this can help you stay aware of
potential discontent. Understanding how people "feel" about your brand
and how this sentiment changes in response to your actions is vital.
This type of analysis, known as "sentiment analysis", will be discussed
in more detail in
Chapter [\[sec-sentiment-analysis\]](#sec-sentiment-analysis){reference-type="ref"
reference="sec-sentiment-analysis"}. Some R packages that help you
scrape data from X through APIs are `rtweet` (Kearney 2019), `streamR`
(Barbera 2018), and `academictwitteR` (Barrie and Ho 2021).

With its massive user base, Facebook has been seen as an ideal platform
for promoting products, ideas, or projects. The connection between users
and the "like" system made it an easy way to collect personal data for
free. These can be harnessed for marketing analysis, especially for
segmentation, where targeting by geographical regions can enhance
communication and promote specific products. Two important R packages
for dealing with data on Facebook are: `Rfacebook` (Barbera et al. 2017)
and `fbRads` (Daroczi, Gopal, and Nagy 2023).

LinkedIn, a popular social-media platform for professionals, was set up
to aid networking. Finding a job through LinkedIn has become a viable
option, and the personal pages can contain a lot of interesting
information, mainly about what occupies most of our time: work. This can
be extracted to check for who might be important partners or influencers
in marketing campaigns. Other analyses could be done to understand
market dynamics, emerging trends, and information about competitors,
including their workforce size or skill sets. To access data through
LinkedIn's APIs via R, you can use `Rlinkedin` (Piccirilli 2016).

Reddit, a very popular platform for sharing opinions and asking
questions about products, recipes, medicines, supplements, and much
more, has become a rich source of data. The impressive quantity of data
and opinions make this social-media platform extremely useful for
marketing analysis. The R package to interact with this platform is
`RedditExtractoR` (Rivera 2023).

All the platforms mentioned above offer, or offered, the opportunity for
researchers to scrape their data through an API. An API consists of
definitions and communication protocols that allow a person with a
computer to connect to a server providing this technology. It is a
privileged gateway to data that needs to be first identified and then
transferred to your computer. APIs generally use a username and password
system, plus or minus other related values, also known as keys. These
alphanumeric sequences are generated for a specific user and work like
credentials. APIs are interfaces; they open a door through which the
user can access data directly from the service's backend. However, it is
rare that you are able to do this immediately, and collecting data
through APIs can be problematic. Significant issues arise due to
constant changes in authorization modes, data access limitations, and
managerial decisions which can restrict access. Several R packages
written for this purpose become obsolete after a few years, or even
months, due to internal changes in social-media data-accessibility
policies and parameters. As such, although scraping with APIs might seem
a good way forward, other methods of obtaining data may be more suitable
for the task you have in front of you. Remember, while working with R
packages that do API scraping, two components must be stable: the
politics of the API provider and the R package.

### Scraping with your browser

Having tools that simplify the data-collection process without requiring
deep technical know-how can be useful and comforting. Take the Web
Scraper plugin for Google Chrome, for example. It is a user-friendly
tool for web scraping, requiring only a basic understanding of HTML and
CSS. You can install it easily from the Chrome store, and, as with most
plugins, a browser restart is needed post-installation. Web Scraper
stands out for its:

-   Ability to navigate and scrape multiple pages with a defined
    structure, like
    "[http://www.example.com/pages/\[1-10\]".](http://www.example.com/pages/

-   Versatility in scraping different data types.\

-   Ability to extract dynamically generated text from client-side
    scripts, including AJAX and JavaScript.\

-   The possibility of reviewing and exporting the local storage of
    scraped data to a CSV file.\

-   The ease in switching between exportable and importable sitemaps
    which detail the scope of a scraping project.

Setting it up involves defining the sitemap (which pages to visit) and
the data to be scraped. During the scraping process, Chrome will display
a series of pop-up windows showing its progress. You will receive a
notification once the scraping is complete. All the data can be browsed
and exported as a **.csv** file, ready to be imported into R for further
analysis. The plugin also allows you to export the sitemap for future
use. Check out the plugin's official webpage for a comprehensive guide
on using this tool. To see the scraping results in action, visit this
book's accompanying website.

#### Other Plugins

The world of Chrome plugins for data scraping is vast and varied. Take
Instant Data Scraper, for example, a plugin that simplifies the scraping
process, requiring minimal technical know-how. It uses AI analysis to
see what data can be extracted from an HTML page, bringing something
unique to your scraper's toolbox. And for those interested in specific
sites, Amazon Reviews Exporter and Amazon Data Scraper are plug-ins
designed for collecting data from Amazon. Wherever the data are, it is
lkely there is a tool ready to help you harvest them. This is true for a
range of sites that are well-known to be rich in data, from Parlor to
Gab, and Yelp to Trustpilot. And it is not just Chrome that offers these
tools, Data Miner, for instance, works with both Chrome and Microsoft
Edge.

Focusing on something more practical, using Amazon Reviews Exporter's
free version, you can download about 10 reviews at a time (be aware that
these parameters might change over time). For example, we could grab
reviews for "The Lord of the Rings Hardcover - Box set, March 3, 1988"
from Amazon, save them as a CSV file, and then dive into the data using
R.

### Scraping by programming

To the non-specialist, a webpage appears as a blend of text, images, and
videos, all presented on a web browser. However, beneath this surface
lies a more complex reality of a double-language presence made of a
markup language and a style sheet that instructs the browser on what and
how to display the content. The structure of the page is governed by
hyper text markup language (HTML), while its visual presentation is run
by cascading style sheets (CSS). HTML has an easy-to-understand syntax.
It gives directives to the web browser and embeds text in HTML pages.
The text displayed on a webpage is (nearly) always enclosed in HTML tags
such as `tag>`Some Text`<tag>`. The text inside the angular brackets
`<>` can be any HTML keyword such as `<html>`, `<body>`, `<h1>`, `<p>`,
among others. The slash inside the brackets `</>` signifies the end of
an element. In technical jargon, the term "element" defines the opening
and closing of two tags and the content between them. Once a tag is
open, it must also be closed, like a bracket in mathematics. There are
some exceptions, though, where the tags are self-contained and do not
require closing, such as `<br>` for a line break. Some HTML tags contain
attributes, such as `id` or `class`. They link HTML elements to the CSS
for the aesthetic styling of the webpage. An important tag in HTML is
`<div>`, used in web design and layout, and is essential for structuring
the site. It is commonly used together with CSS for styling and
JavaScript for functionality, so pay attention to it whenever you find
it. Figure [1.2](#fig-paragraphelement){reference-type="ref"
reference="fig-paragraphelement"} shows the main components of an HTML
element.

Using programming languages, for example, R, Python, or Java, we can
navigate through the internal elements of these web pages and retrieve
valuable information. This process involves parsing the pages into a
document-object-model (DOM) tree structure (Keith and Sambells 2011).
Let us demystify the link between HTML and DOM. When a browser loads a
webpage, it parses the web page sequentially, reading the HTML tags in
sequence. While parsing, it builds the DOM, and the HTML tags are
transformed into DOM nodes. If, during the parsing process, there are
scripts, JavaScripts, for example, or external elements such as CSS
directives and images that might interrupt the process, the DOM building
still goes ahead. Most of the time, in parallel, with little or no
interruptions. So, the DOM represents a model of a page, while HTML is a
language that allows you to create the DOM. After its creation, scripts
can manipulate it to change a page's content, structure, or style after
it has been loaded. This procedure allows for it to be interactive,
making pages dynamic and accessible alike. It is easier to locate
specific data on a webpage through the hierarchical tree structure of
the DOM, and scraping tools can use the DOM to identify `ids`,
`classes`, and `tag names` to extract the information you need. For a
visual representation of how a basic HTML page, like that in the
previous example, is organized by the DOM, refer to
Figure [1.3](#fig-DOMTree){reference-type="ref"

The `<html>` node is the **root** of the tree, it has two branches: the
`<head>` and `<body>`. It tells the browser that it encapsulates all the
elements of the page. The `<head>` node is like the preface of a book.
As well as other elements, it provides meta-information about what lies
underneath the page. The `<meta>` tag adds information about the HTML
page. It does not have a closing counterpart. `<title>`, `<script>`, and
`<link>` are just some of the tags you might encounter in a header. The
`<body>` node contains the main content, structured into headers, such
as `<h1>`, the main content, which can be made up of articles
`<article>`, tables, `<table>`, and unordered lists `<ul>`, and ends
with the footer `<footer>`. `<h1>` is the heading tag with the largest
dimensions. If you want to create smaller headings, `<h2>` to `<h6>`
offer progressively smaller sizes. `<li>...</li>` show that we will
enclose a **li**st between the tags. To make an **u**nordered **l**ist,
you use the `<ul>` tag. Of course, there is a tag for an **o**rdered
**l**ist too which adds numbers or letters in front of `<ol>`. You can
create a table with a unique element that has a table row `<tr>`, within
which is a **t**able **c**ell not defined by the `<tc>` tag, but `<td>`,
which stands for **t**able **d**ata (or cell). For more information on
HTML and CSS, check the additional material on the
https://danieldanlab.github.io webpage.

### Scraping by programming +

Sometimes, scraping web pages based on a static pattern is very
challenging, especially when actions like clicking a link or navigating
to a "next" page are required. In such cases, we need a tool which can
mimic and automate human actions on a webpage. Selenium (2024) has a set
of various open-source software tools, each with a distinct method, to
help do this. Primarily used for automatizing tests concerning the
functionality of websites, Selenium can also be used as a remote
control. It makes it possible for the interface elements on web pages,
for example, links or pop-ups, to be accessed via scripting rather than
through clicking with a mouse. It can even handle JavaScript processes
as well (Garcı́a et al. 2020). The procedures mentioned above are usually
tricky to execute without Selenium due to the problem of integrating
JavaScript with the browser.

Another component is Selenium's ability to identify the agent,
essentially the browser used for scraping. Common choices include Google
Chrome (the default option), Firefox, or Edge, and these can be used in
their standard or headless versions. A headless browser provides
automated web-page interaction without a graphical user interface. It
can be chosen in lieu of commonly used web browsers to minimize
interactions, and so maximizing the user's anonymity. The key packages
used for this task are `RSelenium` (Harrison 2022) and `rvest`. The
former ensures that R and Selenium interact and provides a set of R
bindings from the Selenium WebDriver (Garcı́a et al. 2021), while the
latter handles the scraping. The script starts the Selenium server
sequentially and pauses the system for two seconds, allowing it to be
loaded. Then, it links the driver to the browser, which opens a session
and loads the external file. Eventually, the data is stored in a data
frame and then saved in CSV format. However, be aware of potential
compatibility issues between Chrome and the versions of its driver. In
such cases, switching to Firefox or another browser might resolve the
issue. Also, if a script fails due to a communication port being busy,
consider closing the current session or choosing a different port. For
more detailed guidance, visit our website.

### Using services based on AI to obtain data {#use-services-based-on-ai-to-obtain-data}

Because scraping using traditional software or self-produced code can be
problematic due to changing website layouts, developments in
AI---especially Large Language Models (LLMs)---offer new ways to improve
web scraping, as described in Posedaru et al. (2024). The authors
propose a solution involving a JavaScript application that uses natural
language to extract information and save the scraped results to a JSON
file. The steps include providing a URL address and description of the
data that needs to be extracted. The HTML structure is then collected,
cleaned, and transferred to ChatGPT in several chunks. ChatGPT is used
to detect the appropriate selectors corresponding to the data in the
HTML structure, after which it generates a scraper based on these
elements. Once the scraper is executed, the data is saved in a JSON
file.

There are other ChatGPT-based tools, such as the
gpt-automated-web-scraper, which generates code based on user inputs and
website analysis (Breeuwer 2024), or the ChatGPT Web Scraper API plugin
(OpenAI 2024). These tools enable autonomous data collection using LLMs,
though ChatGPT-like tools cannot scrape websites directly (as of now).
Additionally, several web services use AI to scrape data without the
need for any coding, such as browser.ai, bardeen.ai, and kadoa.com.

All these tools are very promising, although some will endure and others
may fade away. The important thing to understand is how to collect data
while taking into account privacy and ethics.
